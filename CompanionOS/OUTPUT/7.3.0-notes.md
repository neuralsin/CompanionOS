# CompanionOS 7.3.0

## Changes

- Robo uses solid robotic apertures. Removed the actual lens, pupil and glint drawing path.
- Thoughts remain for ten minutes, then fade. Blank/unsupported text receives a printable fallback.
- Off / Playful / Bold personality setting. Every third locally generated thought is flirty when enabled; pushed messages and reminders do not count toward that sequence.
- Local thoughts consider time, playback, available weather and upcoming events. No cloud dependency.
- Calendar (page 18) and Timetable (page 19) preserve all previous page IDs.
- Calendar has a real fourteen-day event-count graph, exams, reminders and completion status.
- Weekly classes include day, start, duration and room. Class alerts begin within two hours of the next class and handle midnight crossings.
- Exam reminders use an eight-second red banner, not a full-screen strobe. Cadence increases from hourly within three days to every five minutes within six hours.
- Hold Select on Eyes, or use Dismiss overlays in the app, to dismiss thoughts and alerts. Exams/reminders snooze for an hour; classes snooze through that occurrence.
- Planner editor supports adding, editing, deleting, completing, snoozing and explicit synchronization. Drafts survive app restarts; conflicting bot revisions are rejected instead of silently overwriting data.
- Schedules and personality are stored in ESP32 NVS. Current capacity: 12 exams/reminders and 16 weekly class slots, approximately 2 KB persistent RAM.
- Screen capture starts paused and can be enabled explicitly. Bluetooth remains off as a connectivity fallback.

## Reboot Investigation

The hardware reboot cause is NOT confirmed. Removed redundant SPI reinitialization after TFT setup and restored brownout detection instead of masking voltage faults.

The firmware logs reset reason, previous execution stage and heap at startup. Ten consecutive fault resets before a minute of stable operation trigger a minimal recovery screen with optional services and animation stopped. Recovery now displays the reset reason/stage and stays offline, skipping NVS and networking startup. Hold Select for two seconds to retry; app commands are unavailable in recovery. Credentials and schedules are not erased.

The November 22 source update addresses the reported panic at stage 5 by releasing optional display buffers before WiFi initialization, checking available startup RAM and driver/event-registration results, and waiting 120 seconds offline after initialization failure. Stage 5 alone does not establish the exact panic cause. New markers distinguish credential loading (51), buffer release/RAM check (52), driver initialization (53), event setup (54), disconnect (55), association (56) and association submitted (57). A subsequent hardware reset/backtrace remains necessary to confirm resolution.

The newly introduced late WiFi initialization has also been reverted: driver startup is back before the boot animation and eye canvases. Only web services/API requests remain delayed after the first page. This restores the pre-regression allocation order rather than assuming an existing hardware fault.

November 23 source marker: `B23W2`. RTC checkpoint fields are now volatile so crash-time stores cannot be optimized away. Recovery shows the previous free heap, largest block and task-stack high-water reading, with the phase where those metrics were sampled. Marker 50 covers entry to WiFi setup; 70/71 bracket the first rendered page. A heap-integrity check runs before releasing display buffers or entering WiFi initialization. The expanded RTC record resets old diagnostic records once, without erasing settings. Theme 3's first allocation now occurs after driver initialization. Host tests passed, but the reported hardware panic has not been reproduced or conclusively diagnosed.

The November 21 source update disables all Bluetooth initialization and tools. WiFi waits 1.5 seconds after the first page, web services at least 3.5 seconds, and standalone APIs at least 6.5 seconds, with additional link-stability gates. Backlight PWM attaches after TFT initialization and fades in. Boot progress updates only changed pixels. Low-memory Robo/Theme 2 rendering uses an eight-row monochrome strip buffer instead of clearing the visible face before drawing. This reduces software repaint flicker but does not establish the cause of hardware resets or backlight flicker.

Supply a complete serial cycle at 115200 baud, including `[boot]`, any Guru Meditation message and backtrace. A brownout or unstable supply still requires a hardware correction; the recovery path is not proof that the fault has been eliminated.

## Installation

Install `CompanionOS-7.3.0.apk`. The deskbot needs one upload of the updated `arduino/CompanionOS_Main` source for the new protocol and firmware features. No firmware binary was generated in this pass. Later schedule, personality, WiFi and Spotify credential edits do not require reflashing.

In the app, open Planner, add entries, then Sync planner to bot. Flirt level is under Deskbot / Appearance. Reload from bot obtains its saved schedule. Sync failures retain the phone draft and do not report success.

The bot requires a valid clock for dated alerts. NTP supplies it online; planner sync also supplies phone time. It continues while powered offline, but a completely unpowered ESP32 without an external RTC must resynchronize after boot. Weekly schedules use the phone's UTC offset at sync; resync after changing timezones or a daylight-saving transition. Built-in TFT fonts currently require printable English titles.
